2026-07-08: after a long autopsy->exits->hours-filter chain, Moises: "you did a
lot of work but i did not get feedback." I had been running/editing/committing
in sequence with results buried in tables or terse status lines.

**Why:** He wants to be IN the loop while work happens, not receive a digest at
the end. Each experiment's outcome should reach him as a 2-4 short lines —
what came back, what it means, what I'm doing next — BEFORE the next step
starts. This is distinct from (and additive to) [[feedback-keep-messages-short]]
and [[feedback-propose-before-building-tools]]: short, propose first, AND a
feedback beat per step.

**How to apply:** Rhythm per step: run -> "Result: X. Means: Y. Next: Z." ->
proceed (or pause if it's a fork). Never chain two experiments without a beat
between them. Tables only when the numbers ARE the point, max ~4 rows.
