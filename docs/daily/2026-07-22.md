   bumped numpy 1.26.4 → **2.5.1**, breaking numba (≤2.2) and scipy (<2.3) → `core_v2`
   wouldn't import. Re-pinned `numpy<2` → 1.26.4. Full stack green (numba/scipy/torch/
   mamba/llama/core_v2 all import).

   (`4e30`) blob on a dead `/mnt/c` path (and gemma4 is truncated: 601/2012 tensors).
   Repointed to qwen3:14b (`sha256-a8cc…`) on the Linux ollama store. `eval_native_ckpt.py`
   also given a `DEFAULT_BLOB_LINUX` (was `/mnt/d/ollama`).
3. **Live engine (broken ~24 days) — FIXED.** `core_v2/sim_executor.py` (5 names) and
   `live/engine_v2.py` (3 names) hardcoded feature-name window suffixes (`_15/_12/_9`)
   that vanished when N_BASE went uniform-30 (2026-06-27, commit 4330a59e) → `ValueError`
   at import. Now resolve dynamically via `f"...{N_BASE[tf]}"`. Both modules import clean.
4. **Mamba training loop — FIXED.** (a) `train_mamba_rl_seq.py` atlas-root used a WSL/
   Windows `os.uname` heuristic hardcoding dead `/mnt/c` & `C:/…/OneDrive` paths →

   code expects `DATA/ai_cusp_picks` (canonical per 7 tools); it was at repo-root →
   symlink `DATA/ai_cusp_picks -> ../ai_cusp_picks`. (c) `reports/runs` was a stray PNG
