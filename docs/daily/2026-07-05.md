# 2026-07-05 — Mamba RL runtime review (RTX 3060 / WSL2)

## What happened
Speed-only review of `research/mamba_zigzag_baseline/pipeline/` per task spec
(profile first, verify 4 hypotheses, fix in order, loss-identity gate).
Full report: `research/mamba_zigzag_baseline/reports/perf/PERF_REVIEW_2026-07-05.md`.

## Headline findings
1. **The shipped torch.compile config crashed on WSL** (reduce-overhead CUDA
   graphs vs carried hidden state → output-aliasing error at step ~2). Prior
   smoke tests passed because Windows skips compile. De-facto baseline was
   eager: **53.15 bars/s**.
2. **Two of the four task hypotheses were stale** — the L=1 scan fallback (a)
   and the pinned single-H2D pack (b) were already in HEAD. The real costs:
   TBPTT backward 32%, double forward 38%, env CPU 16%, syncs 10%.
3. **mamba-ssm fused step() is an autograd trap**: runs under WSL fine
   (wheels: mamba_ssm 2.2.4 + causal_conv1d 1.5.0.post8 cu12torch2.6abiFALSE),
   but backward silently produces None input grads — would train wrong, not
   crash. PureMambaBlock stays for training. Parallel fused scan measured
   **250×** at L=500 → the door for a sequence-restructure later.
4. CUPTI is dead under this WSL driver — no CUDA-time profiler tables at all;
   used host tables + sync-bracketed wall attribution instead.
