# E1 + E2 bench verdicts (2026-07-24, reviewed by Claude; raw: e1_raw.json / e2_raw.json)

Bench set: 3 fixed episodes (2025_01_21), 15 reasoned frames; baseline decode
13.3 tok/s, prefill 12.8s @ ~10k-token prompts. Pre-registered rule: a speedup
that changes outputs is a REJECTION.

## E1 — speculative decoding: BOTH ARMS REJECTED (as benched)
| arm | decode | e2e | equivalence |
|---|---|---|---|
| prompt-lookup | **53.1 tok/s (×3.98)** | ×0.44 (slower!) | MISMATCH 15/15 |
| model-draft 0.6B (CPU draft) | ×0.31 | ×0.23 | MISMATCH 15/15 |

Root causes: the python binding forces `logits_all=True` whenever a draft is
attached → a multi-GB host logits copy per prompt destroys prefill (the ×0.44),
and its speculative sampler is not strictly lossless even at temp 0 (the
mismatches). CPU-resident draft additionally serializes the 14B behind a slow
helper (the ×0.31).

**Keeper finding:** the ×3.98 decode gain is REAL — numeric-dense frames draft
extremely well via n-gram lookup. The prize survives; the binding's path to it
doesn't. **Follow-up (E1b): llama.cpp native server `--draft` route** (no
logits_all tax, upstream lossless speculation), equivalence re-checked.

## E2 — anchor KV cache: REJECTED v1, FIX IDENTIFIED
| metric | baseline | cached |
|---|---|---|
| prefill | 12.84s | 5.45s (**×2.36**; ×1.90 amortized) |
| correctness | — | **FAIL**: max Δlogit 2.35 (tol 1e-4) |

Root cause (high confidence): tokenization-boundary bug — log shows common-
token-prefix 5,691 ≠ system+anchor tokens 5,680. Splitting the prompt text and
tokenizing the parts separately yields a different token sequence than
tokenizing the whole (merges across the boundary) → different logits, honestly
caught by the check. **Follow-up (E2b): tokenize the FULL prompt once, cache KV
at a token-index split of that single tokenization** — never re-tokenize parts.
The ×2.36 prize is real and, with the fix, exactly reproducible by construction.

## Net position
Nothing promoted yet; two real prizes (×3.98 decode, ×2.36 prefill) each one
identified fix away. E1b (server) + E2b (tokenize-once) are the queue. The
equivalence discipline caught both defects before any real run inherited them.

## E2c isolation (same day) — E2 PROMOTED
Three-way test (A one-shot | B two-phase-no-save | C cached): **B==C bitwise
(0.00e+00 on all frames); A differs from both (~1.0-1.4 Δlogit)**. Conclusion:
save_state/load_state is PERFECTLY FAITHFUL; the E2b "failure" was the chunk-
layout difference between one-shot and two-phase prefill — a convention, not a
defect (determinism control showed each layout is itself bitwise-stable).

**PROMOTION with one rule:** the canonical labeling layout is TWO-PHASE
(eval shared prefix, then remainder). Under that convention the anchor cache is
exactly equivalent BY CONSTRUCTION (proven bitwise) and delivers **×2.32 raw /
×1.87 amortized prefill**. All future harness runs (memo pilot, gen-1 gate)
adopt two-phase; cross-generation comparisons stay within-convention.

## Consultant #1 triage (focused speed consult, 2026-07-24)
Independently CONFIRMS: E2c's mechanism (ubatch-boundary reduction order — "expected
fp behavior, not a defect"; load_state restores KV bitwise), E1's failure being the
python wrapper (forced logits_all + own sampler), and the two-speed triage cascade
("the standard answer under frozen weights — keep escalation a fixed function of
logits, calibrated once").

ADOPTED plan (stays on llama.cpp; vLLM/ExLlamaV2 rejected — kernel/quant change
breaks temp-0 equivalence):
- **E3 (server config)**: native llama-server, KV q8_0 (VRAM enabler → full 40/40
  offload, +8-15%), `-np 4` slots (per-slot prefix caching replaces save/load;
  batched decode ~2.5-3.5x aggregate — weight-bandwidth-bound so N streams share
  one weight pass), n_ubatch 1024/n_batch 2048 (0-10%). Est. net ~8-9s/frame
  vs 23s ≈ 2.6x e2e on the 85/15 readout/reasoning mix.
- **E1b (server draft)**: `-md qwen3-0.6b -ngld 99 --draft-max 16` at -np 2 —
  greedy verification = exact-match acceptance → output-preserving BY
  CONSTRUCTION. FIRST MEASUREMENT: draft acceptance rate (≥~65% needed to beat
  pure batching). Our CPU-draft failure was latency, not concept.
- **E1c (optional)**: recover the proven 3.98x prompt-lookup via low-level
  llama_batch per-token logits flags (~200 lines, no logits_all).
- **Equivalence doctrine update**: for batched/speculative paths, equivalence is
  defined at the LABEL level over a large sample (batched greedy ≠ bitwise
  sequential greedy — same E2c mechanism); pin n_ubatch across compared paths.
  KV q8_0 must pass the label-equivalence run or revert to f16.
- Build dependency: native llama-server binary (build llama.cpp with the proven
  gcc-13 + system-CUDA recipe; the python package doesn't ship -np/-md).
