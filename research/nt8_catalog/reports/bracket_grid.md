**Exploration-level.** No stops/management is the baseline elsewhere in this project; this tool asks whether classic fixed SL/TP brackets add anything on top of the calibrated (decile 9 as-is / decile 0 inverted) fire populations. **Fills are close-based only (5s closes) -- no intrabar high/low is used, so stop/target triggers are conservative approximations of what a live bracket order would actually see intrabar.** Mode-first throughout per project convention; read the mode before the mean.

- **Row-level parity on exact-target hits (the real gate)**: 80246 (fire, horizon) pairs re-simulated on the RAW/un-deduped population-A-TEST fires and diffed against `econ_drift_rows.parquet`'s own `drift_5m`/`drift_15m` columns (tolerance 1e-6). Result: **PASS -- 0 on-target mismatches**. This is the correct test that the fills logic reproduces the established convention.
- **Gap-driven divergence (separately quantified, NOT a bug)**: 254/40123 (0.63%) of 5m pairs and 263/40123 (0.66%) of 15m pairs disagree with `econ_drift_rows.parquet` -- but **100% of these occur only when the target elapsed time falls inside a 5s-bar data gap** (quiet periods emit no bar); in every such case this tool's CEILING convention ('first bar with elapsed >= horizon', the literal reading of this task's own bar-by-bar exit spec) disagrees with econ_conversion.py's FLOOR/as-of convention ('last bar with elapsed <= horizon', appropriate for post-hoc drift measurement, not for simulating a live bracket order's timeout). Zero disagreements occur when a bar exists exactly at the target time. The single worst case (day 2025_04_09, fire 12:16 CT) is the well-known tariff-pause volatility spike -- a real large move landing inside a gap, not a computation error.
- My fixed-5m-hold median, population A (decile 9, as-is) TEST, **post-dedup** N=16001: **+2.00 pts** (mean +2.868 [+2.02,+3.69], mode +0.00).
- doc-088 (`econ_conversion.md`) 5m-horizon decile-9-TEST median, **raw/un-deduped** N=40132: **+3.25 pts** (mean +3.862). Raw-vs-deduped deviation: **-1.250 pts**.
- **This deviation is FULLY EXPLAINED and not a fills bug**: applying the identical 60s/same-direction dedup rule directly to the raw decile-9-TEST rows (bypassing this tool's simulator entirely, using only the pre-existing `drift_5m` column) reproduces N=16001 and median=+2.00 exactly -- matching this tool's fixed-5m reference to 2 decimal places. The dedup mandated by this task's spec removes tightly-clustered (within 60s) repeat same-direction fires; those fires apparently skew the 5m statistic upward (median +3.25 -> +2.00) while leaving the 15m statistic essentially unchanged (+1.75 raw vs +1.75 deduped) -- a real, explainable population-selection effect.
- **Spec discrepancy flagged**: the task spec quoted the reproduction target as '+1.75 pts' for the fixed-5m hold -- but +1.75 is actually doc-088's **15m**-horizon median for decile 9 (5m is +3.25). Cross-checked directly against `research/nt8_catalog/comms/088_2026-07-16_ECON_CONVERSION_AND_SHELF_LIFE_MAMBA_GATE_OPEN.md` and `reports/econ_conversion.md` — both show 5m median = +3.25, 15m median = +1.75 for decile 9 TEST. This looks like a horizon mislabel when the spec was written, not a fills bug on either side.
- **Bottom line**: fills are verified correct at the row level (0/80246 mismatches). The aggregate 5m number moves for a documented, reproducible reason (mandated dedup), not because of a bug. Proceeding with the full sweep on this basis.

## Limitations (stated, not silent)

- **Close-based fills only** (5s bar closes) -- no intrabar high/low. A real bracket order would trigger on intrabar excursions this sim cannot see; SL hits are likely UNDER-counted and TP hits likely delayed vs a live fill.
- Day-cap-forced exits (session end, 15:15 CT) are folded into the "timeout" exit_reason bucket alongside genuine TMAX-elapsed exits -- both are time-exhausted exits; `bracket_fills.parquet` does not separately flag which.
- Pseudo-replication: fires are day-block bootstrapped, not fire-independent; per-fire counts are not independent trades. Exploration-level, no live claim.
