## 5. Statement of what "done" means

For a detector to be considered "done", it must pass through the following strict state machine:
1. A written Implementation Plan is submitted (with NO code written).
2. The Reviewer returns an explicit "APPROVED — EXECUTE" verdict.
3. The detector is coded, strictly adhering to any binding mods.
4. The verification script is run, and the output is captured.
5. The raw output is pasted into an Execution Report, explicitly justifying any expected divergences (like Renko truncation).
6. The Execution Report is committed and pushed to the repository.
7. **The Reviewer independently re-runs the code and issues a `✅ VERIFIED` stamp.**

Only at step 7 is the detector "done". Under this definition, Batch A could never have been declared complete by me in Doc 052, as it had neither an approved plan nor a reviewer's verification stamp.
