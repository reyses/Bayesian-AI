## Problem (measured, gen-0 run at 8192 on native Linux / RTX 3060)
Doc 140 pinned the gen-0 rerun at `num_ctx=8192` after the 4096 run was wholly
ctx-truncated. The 8192 run (this session, qwen3:14b `a8cc`, 156 episodes,
crash-safe ckpt) shows the budget is STILL too small, but in a sharply
structured way — per-frame census at 123 episodes:

| frame | tainted | note |
|---|---|---|
| 0 | **0%** | ~5.7k tokens — fits |
| 1 | 20% | ~7.9k — borderline |
| 2 | **100%** | ~8.5–10.7k — always overflows |

Unlike 4096 (silent, global, undetected), this taint is detected + quarantined
(NaN + `TAINTED(ctx_overflow)`), and early frames are genuinely clean.

## Why this cannot stand
The taint is NOT random: it censors 100% of LATE frames. The pre-registered
edge is RIDE-LENGTH; late frames are exactly where the ride signal lives.
Q0 power cannot repair a systematic blind spot in the most informative region
— this is bias, not noise.

## Decision
1. Let the 8192 run complete (cheap; yields the full taint census + clean
   early-frame labels as a comparison artifact). Artifacts kept:
   `gate_state/acceptance_results.jsonl`, `reports/acceptance_native_gen0.csv`.
2. **gen-0b rerun at `num_ctx=12288`** — covers the 10,675-token max observed
   with ~15% headroom. Fresh ckpt/csv (suffix `_gen0b`); same model blob, same
   readout, same packets; taint logic unchanged (any residual overflow still
   quarantines honestly).
3. VRAM price (the taint↔layers trade): KV 8192→12288 ≈ 1.3→1.9 GB → offload
   drops ~38→~35 of 41 layers → est. 20–30% slower/frame. Accepted.
4. `NUM_CTX` stays a module constant; the 12288 run passes it explicitly —
   doc 140's 8192 remains the recorded default until a spec amendment lands.

gen-0b first 3 episodes must show frame-2 `tainted=N` with real p_exit values;
